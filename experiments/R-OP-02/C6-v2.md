# C6 v2: assumption mismatches against persona-core 1.2.1

A delta against R-OP-01's thirteen entries. An entry is marked **closed** only
with the code reference in 1.2.1 that closes it.

**Score: 2 closed, 1 narrowed, 10 unchanged, 1 new.**
**None of them, closed or open, requires a change to the ARCH-010 schema.**

---

## Closed

### M13. A versioned write is two unsynchronised upserts. CLOSED.

`TypedStore.write` now issues **one** deduplicated upsert, supersede links before
new heads (`base.py`, Spec K13 D-K13-1 and D-K13-2). One call is one transaction
on Postgres and one all or nothing operation on Chroma.

`diagnose()`, `repair()`, `plan_relink()` and `current_view()` were added as
well, so a store damaged by an older version can be put right and a damaged
chain stays readable in the meantime.

Evidence here: ten SIGKILL runs, five per embedder arm, all ten consistent, zero
acknowledged writes lost, and **zero `repair` events in any audit log**. The
repair path was never needed because the write path no longer tears. On 1.1.0
this corrupted a node in three of five seeds, unrecoverably.

### M9. `history()` is a full scan, and `rollback()` pays it twice. CLOSED.

`TypedStore.history` now reads the one chain through `get_by_logical_ids`
instead of scanning the store (`base.py`, D-K13-13). The package's own note
measures 216 ms against 1 ms on 3,000 rows. Rollback p50 here fell from 454.9 ms
to 175.9 ms on the same embedder, and to 63.4 ms on `HashEmbedder`.

## Narrowed

### M4. `rollback()` copies the target's metadata verbatim. NARROWED, not closed.

1.2.1 strips a fixed set, `BOOKKEEPING_METADATA_KEYS`, so a conversation id and a
session id no longer time travel with the payload (D-K13-12). Every other
metadata key still comes forward exactly as before. An adopter who keeps its own
bookkeeping in metadata, a revision stamp being the obvious case, still has it
silently carried back with the rollback. persona-core now protects its own keys;
it does not protect yours.

## Unchanged

### M1. No structured slot for a node, so the node is an opaque blob.
`PersonaChunk` is still `text: str` plus `metadata: dict[str, str]`, and the
transport still takes JSON primitives only. The whole node is still canonical
JSON in `text`, so the store still cannot filter or index on any node field.

### M2. The MemoryStore protocol still has no read by id.
`stores/protocol.py` is byte identical between 1.1.0 and 1.2.1. `get_by_ids` is
new but keys on **physical** chunk ids, and its own docstring says the difference
matters: a physical id names one version, a logical id names a chain. A graph
node is a chain, so `get_by_logical_ids` on the `Backend` is still the narrowest
keyed read, and it is still below the typed store, where policy and audit do not
run.

### M3. No store wide revision, and `write()` still returns `None`.
Still synthesised from the `(created_at, id)` order, still needing a read back
after every write to learn what was just written, still unsound the moment two
processes write one store.

### M5. The write policy axis is still the wrong axis.
`WriteSource` still has exactly three values. Role ownership is still enforced
above the store, and `SelfFactsStore` is still FORCE_ONLY for system writes, so
every write still passes `force=True`.

### M6. Per node immutability still has no counterpart.
ARCH-011 interface nodes are still guarded in caller code.

### M7. Unit validation is still not expressible in the store.

### M8. There is still no changed-since read.
This is the entry that decides the experiment. `get_all` is still the only call
that can return every change, so every diff still materialises and revalidates
every version of every node. 754x the baseline at p95 on the better arm.

### M10. The tenancy unit is still a persona, not a project.

### M11. The four typed stores still do not map to the four node kinds.

### M12. An embedding model is still a hard dependency of the package.
Genuinely mitigated at runtime: `HashEmbedder` is new, needs no model, and is
the correct choice for a store nothing searches semantically. Write p50 fell
from 200.6 ms to 55.1 ms and the hundred second cold torch import is gone.

Not closed, because `packages/core/pyproject.toml` is byte identical: still 20
direct dependencies and **137 distributions**, torch and sentence-transformers
among them, installed and shipped even in the arm that never loads a model.

## New in 1.2.1

### N1. The recovery routine exists but nothing calls it automatically.

`repair()` has exactly one caller in the whole repository, the
`persona repair` CLI command. It does not run at store open, and no store runs
it for itself. B calls it at open here only because the criteria's C4 asks a
restarting process to run its recovery routine.

The exposure is smaller than it sounds, for two reasons worth stating: the write
path no longer creates the damage, and `current_view` keeps a damaged chain
readable without repairing it. So this is a residue of the old bug rather than a
live hazard. It matters only for stores written by 1.1.0 or earlier, which will
sit broken until a human types the command.
